# Ежедневник

Приложение-ежедневник на Rust. Сначала Android, затем Windows (код общий).

**Стек.** Ядро на Rust (`core`), оболочка Tauri 2 (`app`), интерфейс на HTML/CSS/JS (`app/ui`), системная часть Android на Kotlin внутри плагина Tauri (`plugins/planner-native`), сервер рейтинга на axum (`server`).

## Что внутри

| Требование | Где реализовано |
|---|---|
| Таблицы-расписания на день и на неделю | `app/ui/app.js` (таблица времени, пересечения занятий делятся на дорожки), данные: `core/src/store.rs`, `planner.rs` |
| Виджеты рабочего стола | `plugins/planner-native/.../Widgets.kt`: «Дела на сегодня», «Расписание», «Неделя». Цвета берутся из выбранной темы |
| Акцентный цвет, темы AMOLED / Material / Liquid glass / Simple | `app/ui/style.css`, `app.js` (`applyTheme`) |
| Анимированные фоны | `app/ui/bg.js`: северное сияние, пузыри, звёзды, волны, переливы; яркость настраивается |
| Напоминание: дата, точное время, иконка | `reminderSheet` в `app.js`, модель `core/src/model.rs` |
| Способ: будильник, уведомление, на весь экран | `Scheduler.kt`, `AlarmReceiver`, `AlarmService.kt`, `AlertActivity.kt` |
| Повторы | каждый день, по дням недели, раз в месяц, «до даты» (`core/src/recurrence.rs`) |
| Распознавание выполнения | статус считается автоматически: впереди, пора, выполнено вовремя, выполнено с опозданием, не выполнено, пропущено. Окно «вовремя» задаётся для каждого напоминания (`compute_status`) |
| Категории | свои название, цвет и иконка |
| Достижения | 16 штук (`core/src/achievements.rs`), очки, уровни, серии дней |
| Рейтинг между пользователями | `server` + `core/src/online.rs`; недельный и общий, «комнаты» для своих |

## Как «распознаётся» выполнение

Приложение не видит, что вы сделали на самом деле, поэтому выполнение подтверждается отметкой: в списке, в уведомлении или на экране будильника. Дальше всё автоматически:

* отметка до срока или в пределах окна «вовремя» даёт 10 очков, позже окна даёт 4;
* если окно закрылось, а отметки нет, дело считается невыполненным и обрывает серию;
* «Пропустить» не считается ни выполненным, ни невыполненным;
* отметку из уведомления при закрытом приложении запоминает Android-слой, а приложение забирает её при запуске **с настоящим временем нажатия**.

## Сборка Android

Нужно: Rust (rustup), Node.js 20+, JDK 17, Android SDK (платформы 36/37, build-tools 37) и NDK 27.2.12479018.

На Windows сборка выполняется одной командой (что установить — см. [BUILD_ANDROID.md](BUILD_ANDROID.md)):

```powershell
.\build-apk.ps1              # подписанный release APK для arm64 + armv7
.\build-apk.ps1 -DebugBuild  # debug APK
```

Готовый файл появится в `dist\dayplanner-<версия>.apk`. Подробности, ключ подписи и решение типовых ошибок — в [BUILD_ANDROID.md](BUILD_ANDROID.md).

Ручной вариант (если переменные окружения уже выставлены):

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
export ANDROID_HOME=~/Android/Sdk
export NDK_HOME=$ANDROID_HOME/ndk/27.2.12479018

# 1. Проверить ядро (тесты лежат в core/tests)
cargo test -p planner-core

# 2. Подготовить приложение
cd app
npm install
npm run icons          # создаёт иконки из app-icon.png
npm run android:init   # создаёт проект Android в src-tauri/gen/android

# 3. Запуск на телефоне или эмуляторе
npm run android:dev
# Готовый APK
npm run android:build
```

После первой установки откройте **Настройки → Android** и выдайте разрешения: уведомления, точные будильники, уведомления на весь экран, работа в фоне. Без них будильники будут срабатывать неточно.

Виджеты: долгое нажатие на рабочем столе, затем «Виджеты», затем «Ежедневник».

## Сервер рейтинга

```bash
cargo run -p planner-server --release     # порт 8787, данные в leaderboard.json
```

В приложении: **Настройки → Рейтинг**: адрес сервера, ник, при желании «комната». Для интернета поставьте перед сервером HTTPS (Caddy или nginx); адрес вида `http://` без HTTPS Android по умолчанию блокирует.

Очки считает устройство, сервер их хранит и сравнивает, а резкий рост очков за один запрос отклоняет. От целенаправленной накрутки это не защищает.

## Просмотр интерфейса без сборки

Интерфейс открывается в обычном браузере (`app/ui/index.html`) в демо-режиме: данные хранятся в браузере, логика упрощена (`demo.js`). Он нужен только чтобы быстро посмотреть вёрстку и темы.

## Windows (следующий этап)

Ядро и интерфейс уже общие: `npm run tauri dev` запускает версию для ПК. Осталось добавить в плагин `planner-native` уведомления Windows и запуск в трее, это заглушка `plugins/planner-native/src/desktop.rs`.

## Структура

```
core/                  ядро: модели, SQLite, повторы, статусы, очки, достижения, API-команды
  tests/core_tests.rs  тесты логики
server/                сервер рейтинга (axum)
app/ui/                интерфейс (HTML/CSS/JS), bg.js: анимированные фоны
app/src-tauri/         оболочка Tauri: одна команда `api`, вызывает ядро
plugins/planner-native Android: будильники, уведомления, экран на весь экран, виджеты (Kotlin)
```

## Известные ограничения

* Будильники планируются на 30 дней вперёд (до 200 штук) при каждом открытии приложения и после любого изменения. Если не открывать приложение дольше месяца (или раньше, если дел очень много и лимит выбран), новые напоминания не появятся: открывайте приложение хотя бы раз в 2–3 недели.
* Виджет обновляется при открытии приложения и раз в 30 минут; отметка в виджете пока не ставится (нажатие открывает приложение).
* Данные хранятся на устройстве; синхронизации между устройствами нет.
